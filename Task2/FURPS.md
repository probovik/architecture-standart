# Общие требования к системам (Common)

| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| U   | Удобство использования (Usability) |              |
| U1    |  Весь интерфейс должен быть построен на основе бренд бука и дизайн системы банка.                                |              |
| U2    | Интерфейс должен учитывать GuideLine принятые в сообществе веб разработке и cookbook                                |              |
|     | ...                                |              |
| R   | Надёжность (Reliability)           |              |
| R1    | системы должна соответсоввать стандарту надежности 99,95 на период мвп, после 99,99                                |              |
|     | ...                                |              |
| P   | Производительность (Performance)   |              |
| P1    | все данные должны загружаться не более 1 секунды для расчетных данных и менее 1 секунды для статических данных это стандарт на период мвп                                |              |
|     | ...                                |              |
| S   | Поддерживаемость (Supportability)  |              |
| S1    | Система должна вести журнал (лог) всех критических ошибок с указанием времени, типа ошибки и контекста.                               |              | 
| S2    | Система должна поддерживать интеграцию с системой мониторинга                                 |              |
| S3    | В системе должен быть настроен алертинг при выявлении аномального поведения работы                                 |              |
| S4    | Система должна автоматически масштабировать горизонтально при повышении нагрузки                                |              |
| S5    | Система должна автоматически восстанавливаться после сбоев                                |              |
| S6    | Все элементы API должны быть документированы по стандарту OpenAPI                               |              |
|     | ...                                |              |
| +R  | + Ограничения (Restricitions)      |              |
| +R1     | Использовать микросервисный подход при разработке новых сервисов с развертыванием в kubernetes                                |              |
| +R2    | При передаче данных пользователя система должна шифровать сетевой трафик HTTPS (TLS 1.2 или выше)   |
| +R3    | система должна соответсоввать стандарту надежности 99,9 время работы 24/7                               |              |
|  +R4   | При выборе инструментов разработки необходимо руководствоваться накопленной экспертизой для баз данных использовать PostgreSQL, язык разработки новых микросервисов Java/Kothlin, в качестве брокера сообщений использовать Kafka, для веб разработки при возможности использовать React.js                                |  в зависимости от владения сервисов команда выбирает себе стэк в котором имеет наибольшую накопленную экспертизу, или изучает новый, данное требование позволит стандартизировать подходы к разработке и углублять экспертизу на всем ландшафте, также постепенно по паттерну strangler fig будем уходить от монолитов и устаревшего и санкционного ПО            |
| +R5     | Каждое принятое решение должно проходить ArchOps процесс(ADR, ADRL)                              |              |
| +R6     | Избегать прямых интеграций с АБС                              |              |
| +R7     | Все сервисы должны использовать паттерн rate limit и load balancer для поддержки требований к нагрузке                              |              |

# АБС (ABS)

| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| F   | Функциональные (Functionality)     |              |
| F1  | Система должна автоматически рассчитывать ставки по депозитам в реальном времени                                |              |
|  F2 | Система должна автоматически рассчитывать персонализированные ставки для клиентов                                |              |
|  F4   | Система должна  автоматически загружать данные о ставки ЦБ                                |              |
|  F5   | Сотрудник бэк офиса должен иметь возможность обработать заявки на открытие депозита, в системе он проверяет все данные после чего принимает решение на открытие депозита или отклонение заявки с указанием причины                                |              |
|  F6   | После принятия решение пользователь должен получить СМС о принятом решении                                |    при оповещении использовать новый сервис оповещений          |
|     | ...                                |              |
| S   | Поддерживаемость (Supportability)  |              |
|  S1   |  Для предотврашения ошибок расчета иметь интеллектуальную систему для выявления аномалий и сообщать о них сотрудникам бэк-офиса, для валидации и подтверждения расчитанных ставок                               |  оповещение осуществлять по почте через новый сервис оповещений            |
| +R  | + Ограничения (Restricitions)      |              |
| +R1  | система должны соответсвовать всем требованиям из таблицы "Общие требования к системам"                                |              |
| +R2  | Для оповещения использовать новую систему оповещений                               |              |
|  +R3   | Необходимо перевести систему абс на кластер с репликами                                |      это позволит справиться с возрозшей нагрузкой на систему а также откроет дверь в горизонтальное масштабирование        |
|  +R4   | Все новые функциональные возможности должны избегать бизнесс логики на уровне бд (PL Sql) это табу |      |
|  +R5   | Новые сервисы создаются на стеке Java, микросервисный подход, для БД используем PostgreSql |  позволит постепенно трансформировать легаси систему по принципу strangler fig, а также избавиться от устаревшего стека Delphi, и перейти на свободную бд т.к. Oracle прекратил поддержку    |
|  +R6   | Необходимо поставить api gate way перед системой   | задачи - распределение нагрузки, service dsiscovery, rate limit, для снижения нагрузки на легаси системы, логирование запросов, мониторинг.|
|  +R7   | Необходимо предусмотреть возможность создания новой функциональности на веб клиенте    | позволит постепенно отказаться от вендора и снять вендорлок, а также обновить АБС банка используя современные подходы |
|     | ...                                |              |
